Problem. The rules that turn a run's results and decisions into facts are written four times: the live RunStore, the importer replay, verify's _Replay and part of company_view.trail. C2 added the unqueued-item rule in three places, and 78a024f threaded fiscal_year_end through four to_observations call sites. The importer imports ten private names from observations and runs.

Solution. One module takes a run's events in timeline order (result rows, queued items, decisions, cosigns) and owns everything that follows from them. The live store, import and verify all drive it. Verify becomes "ledger over in-memory state" compared against "ledger over Postgres".

  • Locality: the next rule change lands in one module, not four
  • Leverage: about 400 importer lines collapse
  • Rule tests run through one interface, in memory
  • Importer stops importing private names
  • Two adapters make it a real seam

Problem. JobManager.create_run makes companies optional even though resume and fact derivation need them. I1 was voting forgetting to pass them. The xbrl router keeps its own task set, crash handler and retry, and xbrl_fetch isn't in RESUMABLE. Adding a run type means editing five or more modules.

Solution. One Run lifecycle module owns create (companies required for company runs), launch, resume/retry and finish-on-crash, and takes the lease internally. Each run type is one entry the lifecycle, observation mapping and review code look up.

  • Interface makes I1-class bugs impossible
  • Delete the xbrl router's lifecycle copy
  • Leverage: new run type = one entry
  • Resume tested once, for every run type

Problem. Callers have to know about two locking systems (a Postgres row lock and a filesystem lease), a deadlock caveat about a second RunStore instance on the same thread, and raw run_dir paths for side artifacts. Since the Postgres-only cut-over, LegacyRunStore's row writers have no live caller.

Solution. Fact application moves to the ledger (#1). Side artifacts go behind a named-artifact interface. One lock concept lives inside the store. LegacyRunStore shrinks to a read-only file-history reader for the importer.

  • Callers learn one lock, not two
  • Deadlock caveat leaves the interface
  • Delete legacy row writers
  • Lease no longer assumes a shared runs_dir

Problem. API readers recompute item state from every decision and cosign row, while company_view reads the stored column. Only a shared FINAL_STATES set keeps them in line. record_cosign does check-then-write without the run lock.

Solution. This folds into #1. Queue, decide and cosign go through the ledger, which is the only writer of the state column. Readers read the stored state.

  • Locality: one owner of item state
  • Cosign race closed inside the module
