All workspaces

Tech stack

Six layers, top to bottom. Every workspace uses the same stack. Claude is called through the Anthropic SDK directly (arp/llm/), and extraction is verified by a second, different Claude model; LangGraph only shapes the per-company flows.

Workspace 1

R&D Lab

Spot themes, test strategies, build indices. Results land in the Postgres run store; taxonomies, frameworks and index calibrations are versioned files under taxonomies/, frameworks/ and indices/.

Workspace 2

Argus

Extract cited data points from disclosures, then score them. Runs, results, citations and review decisions are Postgres tables; documents are files with a Postgres registry and a SQLite parsed-text cache. XBRL Facts is file-only, with no database.

Workspace 3

Transition Intelligence Platform

Monitor holdings and climate transition risk. Holdings and alerts are append-only stores; the monthly run writes bi_published rows that Superset reads through a read-only bi schema.

Workspace 4

StewardIQ

Engage companies, vote and report to clients. Rules are GoRules ZEN decision tables; triggers, tiers and drafts are append-only files under stewardship_streams/, and engagement records are copied to Postgres.

Workspace 5

Data Hub

Feeds, stored data and the security master. The security master is a file (data/identifier_map.jsonl) replaced whole on each upload; everything matched against it lands in Postgres.

Sources: frontend/src/lib/processes.ts for the workspaces and steps, backend/pyproject.toml and frontend/package.json for the stack, and the backend/arp/ modules behind each step.
