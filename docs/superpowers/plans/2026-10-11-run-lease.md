# Run Lease Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run's Lease (`GLOSSARY.md`) holds across machines whatever filesystem backs the shared `runs/` folder. It becomes a Postgres advisory lock instead of `flock` on `runs/<id>/.worker`.

**Architecture:** `run_lease(run_store, run_id)` opens its own connection on a per-DSN `NullPool` engine, takes `pg_try_advisory_lock(<namespace>, hashtext(run_id))`, raises `RunBusy` if another session holds it, and releases it (unlock, then close the connection) on exit. `hold_run`, `LocalJobLauncher` and every `RunBusy` caller are unchanged.

**Tech Stack:** Python 3, SQLAlchemy 2, Postgres 16, pytest with the `pg` fixture.

**Spec:** candidate 3 in `docs/architecture-reviews/architecture-review-20261011-0405.html`, narrowed by grilling:
- Q1: several machines, shared `runs/` folder, so side files stay files.
- Q4 (b): Postgres advisory lock.
- Q5: a separate connection per lease, outside the app pool.
- Q6: the file lease is removed entirely.
- Q7: a dropped lease connection silently releases the lease; accepted, with a `ponytail:` comment.
- Q3: the `RunStore.lock` warning stays (no caller uses two instances inside a lock).
- Q2 reversed: the legacy writers build file-era fixtures for the importer tests, so they stay until the importer is deleted (ADR-0001).

## Global Constraints

- `run_lease` and `hold_run` keep their signatures. `RunBusy` keeps its message `f"Run {run_id} already has a worker"`.
- Advisory lock key: the two-`int4` form `pg_try_advisory_lock(1095913540, hashtext(:run_id))`. 1095913540 is `0x41525054`, "ARPT", and keeps these locks apart from any other advisory lock user.
- Lease engine: `create_engine(run_store.dsn, poolclass=NullPool)`, cached per DSN with `functools.lru_cache`, in `arp/orchestration/jobs.py`.
- No `fcntl` import left in `jobs.py`. `arp/storage/locks.py` keeps its own and is out of scope.
- `retention.py`'s `SIDECARS = {".lock", ".worker"}` stays: old runs still have `.worker` files on disk.
- Comments that describe the old lease become false and are updated: the `run_lease` docstring and `api/routers/xbrl.py:113` ("the OS frees it if a worker dies"). Nothing else is touched.

## Review Focus

1. Two leases on the same run from the same process (two connections) conflict and raise `RunBusy`. Leases on different runs don't. Test below.
2. The lease is released when its body raises, and on a normal exit. Test below.
3. `run_lease` used to create `runs/<id>/` as a side effect (`run_dir` mkdir). Every side file still writes through `run_dir()`, which creates the folder itself. Check that nothing relied on the lease creating it: the full suite must stay green.
4. The theme and xbrl busy-probe pattern (`with run_lease(...): pass`, then launch) still releases before the launcher takes the lease. Existing 409 tests cover it.
5. No connection leaks: after 50 lease cycles, `pg_stat_activity` for the test database has no more connections than before. Test below.

### Task 1: The lease is a Postgres advisory lock

- Modify: `backend/arp/api/routers/xbrl.py:113` (comment only)
- Test: `backend/tests/test_resume_run.py`

**Interfaces:**
- `run_lease(run_store: RunStore, run_id: str) -> Iterator[None]` (contextmanager), same as today. Its body:
  1. `with _lease_engine(run_store.dsn).connect() as conn:`
  2. `got = conn.scalar(text("SELECT pg_try_advisory_lock(:ns, hashtext(:id))"), {"ns": _LEASE_NS, "id": run_id})`, then `conn.commit()`, so no transaction stays open for the run's whole duration. A session-level advisory lock outlives the transaction.
  3. If `not got`, raise `RunBusy`.
  4. `try: yield`, `finally:` run `pg_advisory_unlock` with the same key and commit. Closing the `NullPool` connection also frees it if the unlock fails.
- `_lease_engine(dsn: str) -> Engine`: `@lru_cache`, `create_engine(dsn, poolclass=NullPool)`.
- The docstring says: one worker per run, across processes and machines, via a Postgres advisory lock on its own connection, freed when the holder exits or its connection dies. Plus `# ponytail: a dropped lease connection frees the lease while the worker runs on; a heartbeat that stops the worker is the upgrade path`.
