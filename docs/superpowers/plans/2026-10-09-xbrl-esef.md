# XBRL pipeline, EU market (ESEF) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fetch the latest ESEF annual filing of companies (by LEI) from filings.xbrl.org into the existing XBRL store, and add the ESRS tags to the tag dropdown.

**Architecture:** One new fetch path next to the SEC one, dispatched by `market` (`sec` | `esef`). Facts come from the filing's pre-parsed xBRL-JSON (`json_url`); the report package zip is stored as the second file. Everything downstream (store, tables, selection, verify, API, page) is shared; the entity key stays in the field `cik` (CIK10 for SEC, LEI for ESEF) with a new `market` value beside it.

**Tech Stack:** Python 3.12, pydantic, httpx (`MockTransport` in tests), typer, FastAPI, pytest; React + TypeScript (Vite).

**Spec:** `docs/superpowers/specs/2026-10-09-xbrl-esef-design.md` (builds on `2026-10-09-xbrl-pipeline-design.md`).

## Global Constraints

- Branch off `main`; PR base is `main` (CLAUDE.md). Never merge locally.
- Files only, no database. The extraction pipeline (`backend/arp/extraction/*`) is not modified. `EsefDocumentSource` keeps its behaviour (its tests in `tests/test_esef.py` pass unchanged).
- No test calls the network. Every HTTP test uses `httpx.MockTransport`.
- Downloads are SSRF-guarded and size-capped (`MAX_PACKAGE_BYTES` = 100,000,000).
- Entity key: `cik` stays the field and URL name; ESEF values are 20-character upper-case alphanumeric LEIs; SEC values stay 10-digit CIKs.
- `market` defaults to `"sec"` on every model so existing stored files still validate.
- Fiscal year in tables is the calendar year of `period_end`, never the filer's label.

## Review Focus

1. A LEI typed in lower case or with spaces, or one that is not 20 letters/digits: normalised with `strip().upper()`; an invalid one gives `no_lei` and never touches the filesystem. (Task 5)
2. A company whose only filings have bogus `period_end` values (year 4172, or 1900): `not_found`, never a stored 4172 filing. (Task 5)
3. Two universe rows (different `company_id`) with the same LEI: one directory, both ids in `company_ids`. (Task 5)
4. Fact values that are not finite numbers (`"NaN"`, `"INF"`, `""`, `"1,234"`, text) or are nil: skipped, never crash the run. (Task 3)
5. The same fact twice in one filing (same concept, unit, period): one row. (Task 3)
6. A filing without `json_url` (or `package_url`) is never chosen as the latest, even when its `period_end` is the newest; the index's `error_count` is ignored. (Task 5)
